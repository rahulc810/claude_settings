## 1. observer

### Modeled skill

- **name** `observer`
- **purpose** Audit the *system* — session transcripts, harness config, skill/agent/MCP
  inventory — for waste and friction the model cannot see from inside a single session,
  and propose system-level changes. Report only; never edits a skill.
- **triggers** `observer`, `audit my setup`, `where am I wasting time`, `is my workflow
  working`, `what isn't being used`, `session audit`
- **procedure** (1) fix the window and check subject age; (2) run three fixed lenses over
  `~/.claude/projects/*/*.jsonl` + config; (3) rank findings by cost × confidence;
  (4) write a dated report; (5) route each finding to its store.
- **outcome** `docs/observations/<YYYY-MM-DD>.md` — ranked findings, each with the metric
  that produced it, and a routed action (`notice.md` line / `forge` idea file / settings
  edit / no-op).
- **recurring need** an elaborate setup drifts: 28 skills, 4 MCP servers, agents, hooks,
  265 transcripts across 12 project dirs. Nothing currently measures whether any of it
  is used, or where sessions actually stall.

### Proposer case

**It already happened, and it worked.** `docs/notice.md` 2026-08-02 records exactly this
run, done by hand over 146 sessions: it found 49 user interruptions and 11 compactions,
and correlated them with bare-nudge openings ("continue", "implement") on multi-file
tasks. That correlation became a proposed change to `planit`/`implement`. One manual run
produced a real, actionable, non-obvious finding — the strongest realness evidence any
idea in this repo has had.

**Nothing else can see this.** `notice` captures friction the model happens to notice
*inside* a task. But the highest-value findings are absences: a skill that never fires
cannot notice itself not firing; a session that compacts does not log why; a permission
prompt paid 40 times looks free each time. These are only visible across the corpus.

**The corpus is real, local, and machine-readable.** 265 `.jsonl` transcripts. Tool
calls, interruptions, compaction boundaries, skill invocations, MCP calls and their
latencies are all countable — this is measurement, not vibes.

**The setup is expensive enough to deserve auditing.** The registry carries 28 skills and
4 agents; `CLAUDE.md` mandates 4 MCP stores with a routing table; the global instruction
opens with a cost note ("each extra round-trip re-reads ~84K of cached context"). A
system whose own instructions reason about token cost has a standing interest in knowing
whether that cost is being paid for anything.

**Cheap to carry.** `disable-model-invocation: true`, explicit invocation only — the
always-on cost is two lines of `description`. Runs monthly at most.

### Skeptic case

- **Overlap**
  - **`prune` (steps 5–6)** — the closest neighbour, and a real one. It already sweeps
    `skills/README.md` for orphans, `last-reviewed` staleness, the 120-line size smell,
    and trigger collisions, and it deep-audits a single skill for safety/triggering.
    That is a genuine share of the "is my tooling healthy" goal. **But**: prune reads
    *files* — `SKILL.md`, doc line counts, the registry. It never opens a transcript.
    It can tell you a skill's row is stale; it cannot tell you the skill has fired zero
    times in 90 days, which is the finding that matters. Static inventory vs. observed
    behavior. Different input, different output artifact.
  - **`notice`** — same subject (friction), opposite mechanism and altitude: in-the-moment
    single-line capture during work, vs. after-the-fact corpus measurement. `observer`
    should *feed* `notice.md`, not replace it.
  - **`fewer-permission-prompts`** (built-in) — actually does scan transcripts, and is a
    strict subset: one metric (repeated read-only Bash/MCP calls), one output (an
    allowlist). Observer should call it out rather than reimplement it; permission churn
    is one lens of several.
  - **`forge`** — decides idea→skill. Observer produces ideas; forge consumes them. Clean
    handoff, no duplication.
  - **`teachme`** — session-closing retro, but on *concepts the user may not know*, not on
    system efficiency. No real share.
  - Verdict on overlap: adjacency with `prune` is the one that must be answered in the
    synthesis. The rest are complements.

- **Realness** — one run, on 2026-08-02, four weeks ago, never repeated. "Recurring
  weekly" it is not. The honest frame is *periodic*, like `prune`: valuable at a cadence
  measured in months. That caps Recurrence at 3, not 5.

- **Skill-shaped** — yes, but only if the procedure is fixed. "Find inefficiencies" as
  written is a research prompt, not a procedure, and research prompts produce
  confident narrative instead of measurements.

- **The idea's own history is an indictment.** That same 2026-08-02 notice line records
  the run getting it *wrong*: it reported "planit never fires, agents unused" while every
  skill and agent directory had been created 07-31/08-02 — a 30-day window measured
  against 2-day-old tooling. The user caught it. An observer skill that does not
  hard-code that guard will confidently produce false absences on every run. This is the
  Skeptic's strongest point and it is a design requirement, not a rejection.

- **Context cost** — genuinely cheap. Explicit invocation, no always-on machinery.

### Synthesis

The Skeptic's overlap claim against `prune` is the one that must land, and it does not
quite: the two skills share a *goal* but not an input or an output. Applying the Overlap
check — prune's Procedure is `wc -l`, registry rows, `SKILL.md` line numbers; observer's
is transcript aggregation over a time window — the normalized instruction overlap is well
under 40%, and the artifacts differ (`skills/README.md` edits vs. a dated observation
report). They are complements at different altitudes, and the boundary is stateable in
one line: **prune audits the tooling as written; observer audits the tooling as used.**
Put that line in both skills so the boundary survives.

The Skeptic's realness point stands and is priced in: Recurrence 3, not higher. It does
not reach the ≤ 2 drop threshold — the need is periodic, not absent, and the one time it
ran it paid for itself.

The Skeptic's two strongest hits are both scope hits, and both become constraints on the
draft rather than reasons to drop:

1. **Fixed lenses, not open-ended research.** The argument names three subjects
   (workflow, harness, sessions); the draft turns them into three lenses with named
   metrics, and the skill measures those and nothing else:

   | Lens | Measures | Example finding |
   |---|---|---|
   | **Inventory drift** | invocation counts per skill / agent / MCP server over the window, against the registry | "`postmortem` and `crawl`: 0 fires in 90 days; 3 agent rows never invoked" |
   | **Session shape** | interruptions, compactions, session length, opening-prompt shape, turn counts before first edit | "compaction clusters on sessions opened with a bare nudge — same 2026-08-02 correlation, still true" |
   | **Round-trip waste** | repeated identical read-only calls, permission prompts, serial tool calls that were independent, re-reads of the same file | "40 prompts for one `git -C` form → defer to `/fewer-permission-prompts`" |

2. **A mandatory age guard, stated as step 1.** Before reporting any zero or any decline,
   check the subject's `mtime`/creation date against the window; a zero over a period
   where the subject did not exist is not evidence, and must be reported as
   "insufficient window", never as a finding. This is the 2026-08-02 correction,
   promoted from a `notice.md` line into a hard rule of the skill that would otherwise
   repeat it.

Two further constraints follow from the repo's own invariants:

- **Report only; route, don't act.** Constitution hard rule 1 (no skill invokes another).
  Observer writes findings and names the destination — a `notice.md` line, a
  `docs/skill-ideas/*.md` for `/forge`, a settings edit, `/fewer-permission-prompts` — and
  the human walks it. It never edits a `SKILL.md` and never touches `settings.json`.
- **Every finding cites its metric.** Per the standing reporting rule: name what was
  actually counted, over what window, across how many sessions. A claim with no stated
  count is not a finding.

**Verdict: add as new**, kind `utility`, off-pipeline, explicit invocation
(`disable-model-invocation: true`), tools `Read, Glob, Grep, Bash`, argument-hint
`[window, default 30d]`.
