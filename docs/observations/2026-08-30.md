# Findings, ranked

### 1. The review stage of the pipeline is skipped ~90% of the time — HIGH

`implement` 80 · `land-feature` 62 · but `code-review` **5** and `resolve-review` **3**.
62 landings against 5 reviews. The constitution defines review as a loop
(`open → worked-on → closed`) between implement and finalize; in practice work goes
implement → land. Every other stage of the pipeline is healthy, so this is not disuse of
the pipeline — it is one gate being routed around.
→ **route:** ask whether review is genuinely optional (then say so in
`docs/skill-workflow.md`) or is being skipped under time pressure (then the fix is
`finalize` refusing to run on a plan with no `review.md`).

### 2. Auto mode and your global CLAUDE.md give directly opposite instructions — HIGH

`CLAUDE.md`: *"Use Grep/Glob for search, Read for files. Not bash grep/cat/head/tail/sed."*
Auto mode: *"read files with cat, head, or sed -n, search with grep... rather than using
the dedicated Read, Edit, or Write tools."*
`permissionMode: auto` is set in **1,070 of 1,499** mode records (71%). Consequence:
60% of all Bash calls are file reads and 37% are greps.
This is **not** a compliance failure — it is a configuration contradiction, and the
CLAUDE.md rule is the one losing 71% of the time. Two live rules that cancel each other
cost more than either would alone.
→ **route:** decide which wins and delete the other, or scope the CLAUDE.md rule to
"except in auto mode". `docs/notice.md` line.

### 3. `git -C` compliance is 18%, and it has already caused two logged bugs — HIGH

117 `git -C` vs 535 bare `git`; 34% of all Bash calls open with `cd `, against an explicit
*"Never prefix with `cd`"*. `docs/notice.md` records the damage twice: 2026-08-02 (a
`git add -A` staged the wrong repo after a `cd` silently reverted) and 2026-08-09 (an
interruption reset cwd mid-`implement`). The rule is right, is in the global file, and is
followed one time in five.
→ **route:** a rule stated once in prose and ignored 82% of the time is a candidate for a
hook (reject bare `git` in a multi-repo tree) rather than more prose. `/update-config`.

### 4. Two-thirds of sessions run from the tree root, where no project config loads — MEDIUM

161 of 246 sessions have cwd `/storage1/Documents/code` — the parent of every repo — while
the work itself touches `wow` (8,754 events), `server-scripts` (5,773), `docflow`
(5,665), `erp` (2,757). Project-level skills exist and are used
(`wow/.claude/skills/normalize-nugget`, `wiki/.claude/skills/ingest-unsorted`) but only
load when cwd is that repo. Sessions started at the root cannot see them, cannot see a
repo's `CLAUDE.md`, and land their transcripts in one undifferentiated project dir —
which also makes `/resume` and this audit coarser than they need to be.
→ **route:** start sessions in the repo. `docs/notice.md` line; possibly a shell alias.

### 5. 83% of tool calls are issued one per message — MEDIUM

1,682 of 9,705 assistant messages batch more than one call. The first line of your global
`CLAUDE.md` is the batching rule, with the cost stated ("~84K of cached context" per
round-trip). At 8,023 single-call messages in 30 days this is the largest raw waste
number in the report — though an unknown share of those are genuinely sequential
(call N+1 needs call N).
→ **route:** `docs/notice.md`. Worth re-measuring next run to see if it moves.

### 6. 157 `/clear`s against 6 uses of the continuity machinery — MEDIUM

`/handoff` 5, `/resume` 1, `/compact` 21. You built `brief-local` + `handoff` + `resume`
to carry context across the session boundary, then crossed that boundary 157 times by
hard reset. Either the machinery is too heavy for the moment of clearing, or `/clear` is
mostly ending genuinely finished work.
→ **route:** worth a judgement call, not an automatic fix. If `handoff` is too heavy at
`/clear` time, that is a skill-design finding for `/forge`.

### 7. Hosted MCP connectors are used 2:1 over the local ones — MEDIUM

`claude_ai_mcp-*` 224 calls (erp 138, wiki 75, brief 11) vs `*-local` 110 (erp 46, wiki 42,
brief 22). `CLAUDE.md`: *"Use the `*-local` servers... only reach for them if the local one
is down."* Unknown from transcripts whether the local servers were actually down — the
`wiki-local` flakiness is already noted in `CLAUDE.md` — so this is a real ratio with a
plausible innocent explanation.
→ **route:** check whether `erp-local`/`wiki-local` are reliably up. If they are, the
hosted entries are costing latency for nothing and should be dropped from the config.

### 8. Registry has four dead agent rows — LOW, trivially fixable

See Lens 1. `skills/README.md` and `docs/skill-workflow.md` both still list them.
→ **route:** `/prune`, or delete the four rows directly.

### 9. `/planit` typed 10 times against nothing — LOW

Plus `/coach` (3), `/create-skill` (1). Each is a wasted turn and a silent no-op.
→ **route:** either create them or learn the real names. `/planit` is almost certainly
muscle memory for `/plan-doc` (68 fires).

### 10. 333 repeated identical Bash calls inside single sessions — LOW

Concentrated: one session repeated 148, another 69, another 51 — 30 sessions total. The
long tail is fine; the three outliers are a loop that re-ran the same probe.
→ **route:** no action. Watch whether it recurs next run.
